# Attack your own conclusion

Apply §6 of `docs/operating-manual.md` ("Attack your own conclusion before handing it over") to the current conclusion$ARGUMENTS. Switch roles: for the next few minutes the job is demolition, not defense.

Procedure:

1. Ask, in these words: **"If this conclusion is wrong, what is the most likely way it's wrong?"** Not "is it wrong?" — name the weakest joint. There is always one.
2. Construct the strongest **alternative explanation** for the same evidence. Check whether anything actually *observed* — not assumed — rules it out. If nothing does, there is no conclusion yet, only a preference between two live hypotheses; say so.
3. Hunt for the evidence not looked for: "what observation would I expect if I'm wrong, and did I ever check for it?" One unrun disconfirming test outweighs three confirming ones already run.
4. Try to build a concrete counterexample — an input, a sequence, a state that breaks the claim. For code, actually construct and run it. Failing after an honest attempt is real evidence; not trying is nothing.
5. Timebox it: one genuine demolition attempt, then ship with whatever survived. Endless self-attack is anxiety cosplaying as rigor.

Output: the weakest joint, the strongest rival and what (if anything) observed rules it out, the disconfirming check that was run and its result — then the conclusion, revised or confirmed, stated plainly.
